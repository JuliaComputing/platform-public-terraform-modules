# RDS PostgreSQL Module

Creates a PostgreSQL RDS instance for the JuliaHub Platform's external database.

## Features

- **Encrypted storage** with autoscaling up to `max_allocated_storage`
- **SSL enforced** via the `rds.force_ssl` parameter, which the platform expects
- **Generated master password**, exposed as a sensitive output
- **Enhanced monitoring and Performance Insights**, with the monitoring IAM role created automatically
- **Optional CloudWatch alarms** for CPU, freeable memory, and free storage
- **Snapshot restore** via `snapshot_identifier`

## Usage

```hcl
module "rds" {
  source = "./modules/rds"

  identifier         = "juliahub"
  postgresql_version = "16"
  instance_class     = "db.m7g.large"

  subnet_ids = module.vpc.private_subnet_ids

  # Only allow the EKS cluster to reach the database.
  allow_from_security_group_ids = [module.eks.cluster_security_group_id]

  tags = {
    Environment = "production"
  }
}
```

Wire the outputs into the platform chart:

| Output | Helm value |
|--------|-----------|
| `address` | `postgres.host` |
| `port` | `postgres.port` |
| `username` | `postgres.username` |
| `password` | `postgres.password` |

The platform also needs `postgres.type: external` and `postgres.requiresSSL: true`.

## Network access

Ingress is **closed by default**. Grant access with one of:

- `allow_from_security_group_ids` — preferred. Pass the EKS cluster security group so only cluster workloads can connect.
- `allow_from_cidr_blocks` — for access from outside the cluster.

Setting neither leaves the instance unreachable.

`publicly_accessible` defaults to `false`, and `subnet_ids` should be private subnets. Leaving `subnet_ids` empty places the instance in the account's default VPC, which is not recommended.

## Passwords

The master password is generated by the `random_password` resource and stored in Terraform state. Treat state as a secret.

The generated password excludes special characters, so it can be embedded in a connection URI without escaping.

When restoring from a snapshot, credentials come from the snapshot; `password` and `connection_string` are then `null`.

## Upgrades

`allow_major_version_upgrade` defaults to `true`, but a major version change still only happens when you change `postgresql_version` and apply.

`apply_immediately` defaults to `false`, so modifications land in the next maintenance window. Set it to `true` to apply at once, accepting a possible brief outage.

Bumping `postgresql_version` changes the derived parameter group family, which replaces the parameter group. The module uses `name_prefix` with `create_before_destroy` so this happens without a naming conflict.

## Alarms

Alarms are created only when `alarm_sns_topic_arns` is non-empty:

```hcl
alarm_sns_topic_arns = [aws_sns_topic.alerts.arn]
```

## Outputs

| Output | Description |
|--------|-------------|
| `identifier` | Instance identifier |
| `arn` | Instance ARN |
| `address` | Hostname |
| `port` | Port |
| `username` | Master username |
| `password` | Generated master password (sensitive) |
| `database_name` | Created database name, if any |
| `engine_version` | Running engine version |
| `security_group_id` | Security group controlling access |
| `connection_string` | Full connection URI (sensitive) |
